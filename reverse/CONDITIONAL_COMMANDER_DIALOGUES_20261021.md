# Conditional commander kill lines

- Request: allow a commander to speak specified fixed/random lines when defeating a particular commander, with configurable conditions.
- Schema 1 remains compatible with existing kill/occupy/retreat arrays. Each commander can now add ordered `killRules` with a unique id, when conditions, chance (0-100, default100), selection (first/random, default random) and nonempty lines. Conditions include victim definition IDs, victim categories/commander presence, scenarios, inclusive round bounds and killer remaining-health percentage. Condition fields combine with AND; array members use OR. Validation checks types, bounds, duplicate rule IDs, conflicting conditions and victim commander references.
- WorldBattle emits a `battle.kill_context` notice containing the actual killer unit and victim unit for commander-led kills. This includes victims with commanders, final faction losses, counterattack, mutual deaths and splash. The existing 8% path still has its original gates and random calls; adding context consumes no combat RNG. WorldNotice gained an optional Target property. The original generic notice also names its victim so the frontend can replace only the matching shout.
- The frontend examines each real kill context in notice order, uses the first condition/probability-successful rule, and queues one fixed/random line. Rule probabilities and line choices use presentation randomness. Conditional rules are evaluated independently of the generic 8% gate; chance100/selection:first uses no presentation random sample. If no rule fires, only the original ordinary-notice behavior applies. One attack may queue separate lines for multiple victims. A removed killer uses zero remaining health and the prior commander portrait. Existing scenario-dialogue priority and local acknowledgement remain.
