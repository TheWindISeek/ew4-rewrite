# Commander dialogue JSON extension

- Request: reserve a JSON interface for exclusive commander lines, including newly added commander definitions.
- API 2 entry: `rewrite/extension.json` field `commanderDialogues` references a schema-1 JSON file with `commanders` keyed by complete definition ID. Each value has `kill`, `occupy`, `retreat` arrays. The existing kill presentation consumes `kill`; the other arrays are reserved and do not add triggers. Missing/empty kill arrays retain the six generic lines and the existing trigger probability.
- `CommanderDialogues.cs` and `ExtensionLoader` validate schema, JSON keys/path, nonempty text, count/length bounds and runtime commander references. Files participate in the existing extension/Mod fingerprints. Omission preserves the original fingerprint path.
- `ClientGame` forwards the configuration in catalog data and exposes `commanderDefinitionId` for scenario and owned commanders. The frontend matches this ID rather than translated name, portrait or owned-instance ID. Different scenario definitions sharing one portrait remain separate; the template demonstrates Napoleon IDs 1 and 20104. Newly imported definitions use the same lookup.
- Author template and instructions: `rewrite/mod-kit/examples/commander-dialogues/`. Configuration and rule-guide indexes link to it. No default dedicated lines were installed into the base game.
- Validation: extension 43 + common skills 68 + dedicated dialogue 73 checks; full client 2285 checks including owned-commander deployment identity; Web build 0 warnings/errors. The template copied under build was packed/validated and imported/activated through the Web API. Browser integration passed 29 checks, six dedicated-line viewport samples, generic/empty-list fallback, identity despite shared portrait, builtin switching and zero exceptions/missing assets. Existing generic dialogue suite passed 85 checks on the new service. Browser presentation tests inject existing kill notices and do not change/retest combat probability.
