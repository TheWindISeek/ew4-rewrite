# EW4 Rewrite 重构与 Mod 创作 — 产品需求说明（PRD）

**文档版本**：v0.1（讨论稿）  
**产品名称**：EW4 Rewrite — 引擎与 Mod 创作平台（fork 演进方向）  
**状态**：待评审  
**关联仓库**：ew4-rewrite（基于上游 0.2.x）

> 本文为产品需求原文。架构讨论中产生的差异见文末"修订备注"。

---

## 1. 背景与问题

EW4 Rewrite 已具备可玩的 Web/Android 客户端、内置原版资源、离线 Mod 导入与规则扩展（API 1/2）。当前实现将 **规则解析、Mod 安装、整局玩法、局外养成、UI 宿主** 缠在一起，命名（如 Legacy）与职责不清，作者做关卡/将领 Mod 主要依赖改 XML/BTL 和命令行工具，**缺少本地/手机可用的关卡编辑体验**。

Fork 方希望：**引擎可持续升级**，**Mod 制作与引擎优化分开演进**，**Client 只承担「运行一局游戏」**，并为 **Mod 包、将领、关卡（在已有地图上）** 留出明确空间；**全球新大地图** 由引擎团队制作，不交给 Mod 编辑器。

---

## 2. 产品愿景（一句话）

玩家用同一套客户端（电脑/手机）玩原版或 Mod；作者在**不碰引擎源码**的前提下，制作并分享 Mod（关卡、将领、规则）；引擎团队可独立升级规则与内置地图，Mod 通过版本与能力声明兼容或明确提示升级。

---

## 3. 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| **玩家** | 使用 Web 或 Android 单机游玩 | 稳定、存档不丢、切换 Mod 不串档 |
| **Mod 作者** | 做改版、新关卡、新将领、规则微调 | 能编辑、校验、打包、导入；不依赖复杂命令行 |
| **引擎/维护者** | 维护 Core、内置 data、发行包 | 改引擎不拖垮 Mod 工具链；架构可测、可拆分 |
| **地图制作（引擎内）** | 维护东亚等大地图 | 策划 JSON 在 `build/workspace/`，Seal 进 `install/web/packs/<id>/`，与 Mod 关卡分离 |

---

## 4. 产品目标（可衡量）

| 目标 | 说明 | 验收方向 |
|------|------|----------|
| G1 | **架构可理解** | 新贡献者能在 30 分钟内说清：引擎 / 内容包 / 会话 / 宿主 / 创作 五层 |
| G2 | **Client 职责单一** | 「运行一局」的 API 与「总部/商店等」可文档化分离，不阻塞游玩主线 |
| G3 | **Mod 与引擎解耦** | Mod 导入/打包不强制依赖「完整游戏 Client」；引擎发版有明确兼容规则 |
| G4 | **关卡可创作** | 作者在 PC/手机浏览器完成：选内置地图 → 编 BTL → 校验 → 导出/装入 Mod |
| G5 | **大地图边界清晰** | Mod 工具不提供「画新世界 BIN」；只选已有 map id |

---

## 5. 非目标（Out of Scope）

- 重做全球地形编辑器（Mod 侧）。
- 替代上游全部前端 parity 或第三方 APK 全兼容（保持现有验证边界）。
- 在线联机、账号云同步、商业化支付。
- 将 EW6 编辑器二进制格式直接当作 EW4 格式（仅可参考交互）。
- 本 PRD 阶段 **不规定** 具体 C# 项目重命名排期（由技术方案承接）。

---

## 6. 用户故事（摘要）

### 6.1 玩家

- 作为玩家，我希望解压 Web 包或安装 APK 后能直接玩内置战役/征服，**以便** 零配置体验。
- 作为玩家，我希望在菜单导入 Mod 并启用后，**原版存档与 Mod 存档分开**，**以便** 切换内容不损坏进度。
- 作为玩家，我希望继续上次游戏时，若 Mod 或规则已变，**明确提示无法加载**，**以便** 不会 silent 坏档。

### 6.2 Mod 作者

- 作为作者，我希望在**已有地图**上放置势力、部队、建筑与事件并保存为 BTL，**以便** 做新关卡而不做新大陆。
- 作为作者，我希望编辑将领定义与头像并打进 Mod 包，**以便** 分享自定义名册。
- 作为作者，我希望用 `extension.json` 等声明规则扩展，**以便** 不改引擎源码也能调技能/胜负等（在 API 支持范围内）。
- 作为作者，我希望保存前看到**与游戏一致的校验结果**，**以便** 减少「能打包不能开局」。
- 作为作者，我希望在手机上也能完成**基础关卡编辑或校验**（横屏），**以便** 不依赖 PC。

### 6.3 引擎维护者

- 作为维护者，我希望新增引擎能力通过**新数据文件 + 注册**接入，**以便** 不修改 Web 里写死的文件列表。
- 作为维护者，我希望 Mod 工具链与 Session 宿主可分开测试与发布，**以便** 优化 Core 时不反复改 Mod 导入 UI。

## 7. 功能需求

### 7.1 运行与宿主（P0 — 保持/澄清）

| ID | 需求 | 优先级 | 备注 |
|----|------|--------|------|
| FR-R01 | 提供 Web 与 Android **同一套**游戏界面（现有 wwwroot） | P0 | 现状已满足 |
| FR-R02 | 游戏逻辑在服务端 C#（Session），前端只调 API | P0 | 现状已满足 |
| FR-R03 | 内置 `rewrite/data` 作为默认内容包，可独立发行 | P0 | 现状已满足 |
| FR-R04 | 文档明确：**玩家路径** = 选内容包 → 开局/读档 → 游玩 → 存档 | P0 | 需产品化说明 |

### 7.2 内容包与 Mod（P0）

| ID | 需求 | 优先级 | 备注 |
|----|------|--------|------|
| FR-M01 | 支持导入 APK / ZIP / 预打包 Mod（含清单与文件哈希） | P0 | 现状 |
| FR-M02 | 启用 Mod 后，资源按路径覆盖内置包；切回原版恢复内置 | P0 | 现状 |
| FR-M03 | 存档按 **Mod 标识 + 规则指纹** 分目录隔离 | P0 | 现状 logicRevision |
| FR-M04 | 删除已安装 Mod 时，**默认保留**该 Mod 对应存档目录（可提示用户手动清理） | P0 | 与现状一致 |
| FR-M05 | 导出/打包 Mod 供他人导入（命令行或 UI） | P0 | ModTool；UI 可加强 |
| FR-M06 | Mod 与内置包 **baseRevision** 不匹配时，导入失败并提示重新转换 | P0 | 现状 |

### 7.3 会话与存档（P0）

| ID | 需求 | 优先级 | 备注 |
|----|------|--------|------|
| FR-S01 | 局外账户（名册、勋章等）与局内 Session 分离存储 | P0 | account.json + slot |
| FR-S02 | 读档校验内容版本；不匹配则拒绝并说明原因 | P0 | contentRevision |
| FR-S03 | 多模式（战役/征服/教程等）存档槽位行为与现版一致或文档化 | P1 | |

### 7.4 架构重构（P1 — 产品层需求，非实现细节）

| ID | 需求 | 优先级 | 备注 |
|----|------|--------|------|
| FR-A01 | **会话宿主（Client）** 职责定义为：当前局状态、RPC、存读档、与内容包绑定 | P1 | 瘦身目标 |
| FR-A02 | **内容解析层**（现 Legacy）对外称「原格式/内容适配」，与 `data/legacy` 目录在文档中区分 | P1 | 命名与文档 |
| FR-A03 | **Mod 安装/验证** 与 **对局运行** 在依赖上可拆分（不同程序集或可选组合） | P1 | 解耦目标 |
| FR-A04 | **内容读取** 支持扩展注册新 logical path 类型，避免宿主写死文件枚举 | P1 | 引擎演进 |
| FR-A05 | 引擎能力列表与 Mod `apiVersion`/扩展声明可对照（不兼容时前置失败） | P2 | 多版本 Mod |

### 7.5 创作工具 — 关卡（P1）

| ID | 需求 | 优先级 | 备注 |
|----|------|--------|------|
| FR-E01 | 提供**关卡编辑**入口（Web，Android 同 WebView 可访问） | P1 | 新能力 |
| FR-E02 | 仅允许选择**引擎已内置**的地图 id，不提供绘制新全球 BIN | P0 | 边界 |
| FR-E03 | 编辑结果保存为符合 EW4 的 **BTL**（及已有扩展：JURI/VICT 等侧车或工具链） | P1 | 可参考 EW6 编辑器 UX |
| FR-E04 | 保存/导出前执行与引擎一致的 **校验**（至少能开局） | P1 | 复用 Verify/Validate |
| FR-E05 | 编辑过程**不占用**当前正在玩的对局状态 | P1 | Authoring 独立 |
| FR-E06 | 支持将关卡产物 **装入 Mod 包** 并走现有导入流程 | P1 | |

### 7.6 创作工具 — 将领与规则（P2）

| ID | 需求 | 优先级 | 备注 |
|----|------|--------|------|
| FR-E07 | 将领：编辑定义、头像资源，生成 Mod 内 `def_commander.xml` 等 | P2 | 可先表格/外部 JSON |
| FR-E08 | 规则：通过 `rewrite/extension.json` 及文档化 JSON 模板配置 | P1 | 现状偏作者手写 |
| FR-E09 | 提供示例工程（如民国 Mod 式）说明「源文件 → 构建 → .ew4mod」 | P2 | 文档+模板 |

### 7.7 大地图（引擎内，P2）

| ID | 需求 | 优先级 | 备注 |
|----|------|--------|------|
| FR-MAP01 | 新地图仅在引擎仓库流程产出并进入 `rewrite/data` | P2 | 非 Mod PRD 核心 |
| FR-MAP02 | Mod 仅通过 BTL 引用 map id，文档说明不可自带未内置 BIN（除非未来单开政策） | P1 | 边界声明 |

## 8. 非功能需求

| ID | 类别 | 要求 |
|----|------|------|
| NFR-01 | 离线 | 游玩与 Mod 导入不依赖外网（除可选更新下载） |
| NFR-02 | 安全 | 资源路径白名单、导入大小上限、跨站 API 限制（保持现 Web 策略） |
| NFR-03 | 可测试 | 规则变更必须可跑自动化验证（Verify / Mod 校验） |
| NFR-04 | 兼容 | 旧玩家存档在**同一内容包与规则指纹**下可继续；换 Mod 不保证跨包兼容 |
| NFR-05 | 性能 | 编辑器在常见笔记本与横屏手机上可流畅编辑「单剧本规模」地图（具体指标后续定） |
| NFR-06 | 许可 | 保持免费、开源、非商业化边界（见 ARCHITECTURE） |

## 9. 核心用户流程（简化版）

### 9.1 玩家：玩内置版

```text
启动 → 主菜单 → 选模式/剧本 → 开局 → 游玩 → 存档 → 退出
```

### 9.2 玩家：玩 Mod

```text
主菜单 Mod → 导入包 → 校验通过 → 启用 → 选剧本 → 开局（独立存档目录）→ 游玩
```

### 9.3 作者：做关卡 Mod（目标流程）

```text
打开创作入口 → 选内置地图 → 编辑 BTL（势力/兵/建筑/事件）→ 校验
→ 导出 BTL 或一键打包 Mod → 本机导入启用 → 试玩
```

### 9.4 维护者：发引擎新版本

```text
更新 Core/data → 更新 baseRevision/能力说明 → 验证内置与示例 Mod
→ 发布 Web/APK → 旧 Mod 若 baseRevision 不符提示作者重新 pack
```

## 11. 成功标准（发布门槛）

**阶段 A — 文档与边界（无代码也可验收）**

- [ ] 发布本文 PRD + 一页「玩家 / 作者 / 维护者」流程图  
- [ ] 明确 Out of Scope：Mod 不做全球地图编辑器  

**阶段 B — 架构解耦（技术里程碑）**

- [ ] 产品文档中 Session / 内容包 / Mod 安装 三者职责无重叠表述  
- [ ] Mod 打包路径可在无「当前对局」环境下完成 validate  

**阶段 C — 关卡创作 MVP**

- [ ] PC 浏览器：打开编辑器 → 选图 → 改 BTL → 校验 → 导出并导入试玩  
- [ ] 至少 1 个端到端示例 Mod（仅改关卡）文档化  

**阶段 D — 移动端创作（可选）**

- [ ] Android WebView 可打开创作页并完成「校验 + 导出到 Mod 导入」主路径

## 12. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| EW4 BTL 无完整 round-trip 编辑器 | 关卡创作范围受限 | 先结构化编辑 + 扩展段工具；全字节编辑标为专家模式 |
| 重构影响 0.2.x 行为 | 回归量大 | 分阶段；每阶段 Verify 门禁 |
| 作者期望「做新大陆」 | 范围蔓延 | PRD Out of Scope + 文档写清 map id 列表 |
| Mod 与引擎版本碎片化 | 支持成本高 | baseRevision + apiVersion + 能力表 |

**依赖**：上游 ew4-rewrite 规则与资源格式；现有 ModTool / Verify；可选参考社区 EW6 编辑器交互。

## 修订备注(v0.1 → 架构讨论后的差异)

以下是架构讨论中与 v0.1 原文不同或需要澄清的点。**原文保持不变**,待 PRD 下一版吸收。

| 原文 | 讨论后的理解 | 影响文档 |
|---|---|---|
| FR-E03 "保存为符合 EW4 的 **BTL**" | 编辑器**读写 JSON**(原生格式);BTL/XML 经 Exporter 生成,用于兼容与验收。见 [ADR-0003](../adr/0003-json-native-format-bidirectional.md) | [03](../arch/README.md) |
| FR-E02 / FR-MAP02 "不可自带未内置 BIN" | 默认只选已有地图 id;**后期**可上传/编辑地图,但必须经 MapPolicy 校验(尺寸、地形枚举、城市落点、可达性等),且单独立项 | [03 §7](../arch/README.md#7-地图) |
| FR-M02 "资源按路径覆盖内置包" | 原版是 `base` Pack,Mod 与其同格式;同一时间只激活一个 Pack,不做多 Mod 叠加。见 [ADR-0002](../adr/0002-pack-model-single-active.md) | [03](../arch/README.md) |
| FR-M06 / FR-A05 `baseRevision`、`apiVersion` | 拆为四个版本号:`formats`、`capabilities`、`behaviorVersion`、`saveSchema`。见 [ADR-0007](../adr/0007-four-version-numbers.md) | [06](../arch/versioning.md) |
| FR-S02 读档校验 | 现阶段不做存档迁移:任何不匹配且无法由兼容开关还原的存档一律拒绝。见 [ADR-0006](../adr/0006-reject-incompatible-saves.md) | [04 §1.1](../arch/README.md) |
| FR-E08 `extension.json` / Lua | Lua 保留为逃生舱,稳定逻辑走 C# 加 JSON。见 [ADR-0005](../adr/0005-lua-as-escape-hatch.md) | [03 §8](../arch/README.md#8-脚本lua) |
| 第 9.3 流程"导出 BTL 或一键打包 Mod" | 增加"实时预览":编辑中可随时切换到草稿试玩,不必先导出 | [05 §4](../arch/authoring.md#4-实时预览) |
| 第 11 节阶段 C 之前 | 增加前置门槛:导入/导出往返验收通过 | [07 P1](../task/done/refactor.md) |
