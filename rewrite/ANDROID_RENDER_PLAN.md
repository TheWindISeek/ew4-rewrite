# 渲染与跳过回合联合优化规划

日期：2026-10-21。关联目标：[RW-01、RW-03](GOALS.md)。

用户已授权当前会话实施，另开新会话补入胜利结算；共享文件与最终状态同步约定见 [分工交接](HANDOFF_VICTORY_SETTLEMENT.md)。第一轮实现及验证见 [实施记录](../reverse/RENDER_SKIP_20261021.md)：按需/遮挡/后台调度、30fps、可见对象准备、地形缓存、DPR预算、AI批次和地块增量已接。以下保留原始规划，用于继续核对尚未完成的真机性能、总内存与粒子预算等工作。

用户反馈：手机 APK 卡顿、容易发热，跳过回合也仍很慢。按用户要求，将 RW-01 手机渲染优化与 RW-03 回合加速合并为同一规划，共同目标是减少等待时间、无效渲染和持续负载；电脑与 Android 共享路径一起考虑，手机单独持续验收。保留现有文档路径便于续接。

已完成隔离桌面基线和开发回归，跳过新局样例约33.1秒降至20.5秒，暂停/后台/静止及跳过期间停止战场绘制。尚未连接Android设备或重新打包；反馈机型、Android/WebView及APK版本、温度/耗电和真机CPU/GPU数据仍待补齐，不能视为手机验收通过。

## 现状与依据

- 已有静态视窗缓存、部队动画帧缓存、文字缓存和屏外绘制裁剪，见[已有优化记录](../reverse/RENDER_PERFORMANCE_20261019.md)。当时的桌面浏览器结果不能代替 Android 实测。
- `Ew4.Web/wwwroot/app.js` 的 `render()` 每次继续请求 `requestAnimationFrame`；战场显示时即使没有操作也进入整帧绘制，尚无按活动情况调整帧率的调度。HD 绘制 DPR 最高为 3，相同 CSS 面积下为 DPR 1 的 9 倍像素面积；实际设备 DPR 和 GPU 耗时需测量。
- `Ew4.Web/wwwroot/battlefield.js` 的 `units()` 每帧复制并排序全部部队，之后才判断可见；部分地块、旗帜和标注路径仍扫描全表。当前裁剪减少了绘制，但没有消除所有屏外对象的遍历和准备成本。
- `staticGround()` 的缓存包含完整变换矩阵，并以状态对象引用判断失效；平移/缩放和更换状态对象均可能重建，需统计哪些重建实际涉及地形或归属变化。
- 可见部队除本体外仍有血量弧线、徽标、旗帜、军衔、头像等多个绘制步骤；港口旗帜、目标圈、徽标脉动、火焰等存在持续动效。`effects.js` 的屏外裁剪仍需部分事件、边界和粒子计算。
- 部队动画帧缓存已有 8M 像素预算（像素内容约 32MiB），但不等于所有 Canvas、图片、文字及 GPU 副本的总内存预算。
- 当前 `MainActivity.cs` 未见显式 `OnPause/OnResume` 渲染协同，前端未见可见性调度。浏览器可能自行节流，不能据此认定后台仍满速运行；需真机验证。
- RW-03 跳过路径仍逐次请求 AI 动作并安装状态，需把规则计算、桥接/序列化、HUD 更新、缓存失效及实际绘制分别计时，不能认定仅优化画布即可解决跳过慢。

## 优化顺序

| 阶段 | 规划 | 验收重点 |
| --- | --- | --- |
| P0 联合基线 | 在隔离测试档中增加可关闭的性能计数，记录帧耗时、可见帧间隔、实际绘制次数、全量/可见对象数、缓存命中与重建、粒子数、像素面积、内存和 AI 跳过各阶段耗时。 | 同一设备/版本/存档/镜头下对比普通与跳过模式，记录整轮等待、累计绘制、请求次数和各阶段耗时；区分 JavaScript 与 GPU/合成，避免仅用平均 FPS 判断。 |
| P1 统一调度 | 合并重绘请求；无变化不重画整张战场。区分正常演出、快速结算和不可见状态，按需调度动画与刷新；完全遮挡的战场停止绘制。接入页面可见性和 Android 生命周期。 | 无可见动画/交互时只在失效后重绘；快速结算不逐动作制造演出和重画整张地图。触摸、资源完成、状态更新和恢复前台及时刷新。 |
| P1a 回合快路径 | 跳过时停止创建中间移动/攻击/粒子演出，取消已有表现等待；合并 HUD 更新、排序和缓存重建。按有界批次推进 AI，评估减少重复桥接、完整快照传输及解析的收益。 | 点击跳过至恢复玩家操作的等待缩短，中间绘制/请求减少；事件需选择、胜负、玩家回合和错误等边界立即返回。保持规则、随机顺序与存档恢复语义，批次不得长期占用主线程。 |
| P2 对象 | 建立视窗可见对象列表；按六角行列范围或分区查询地块/单位，包含跨格移动及大贴图安全边距。排序按状态/位置变更更新，避免每帧复制排序全部单位；阵营、坐标及不变徽标信息按相应数据版本复用。 | 镜头外对象不进入逐帧绘制准备；遍历、排序及分配次数下降。边缘进出不闪烁，移动/死亡单位不漏画，重叠遮挡顺序正确。 |
| P3 缓存 | 拆分地形、归属/设施、部队及界面失效原因，按实际变更更新；测量后再选择地图分块/留边缓存。合成不变的单位装饰，动态血量、旗帜和选中状态按需更新。 | 单位动作不使无变化的地图层整层重建；平移复用有效内容。保留原层级，不将所有层无条件拆成全屏 Canvas，避免内存和合成成本反增。 |
| P4 像素与特效 | 设计标准/省电/高画质档及独立帧率、战场渲染比例；优先试验手机 30fps、战场 DPR 1～1.5，保留 60fps 选项。缩远时简化次要装饰；限制可见粒子与透明叠加，复用特效边界和纹理。 | 比较视觉质量、操作延迟、帧耗时和发热后再决定默认档；文字、按钮和点击坐标保持清晰准确。关键信息始终可辨识。 |
| P5 内存与切换 | 为全部画布/纹理缓存统计总预算、命中率和淘汰次数，按设备能力设置上限；切图/切 Mod/退出对局释放旧引用，热点对象按测量结果复用。 | 连续切换及长局内存无持续增长；预算过小不反复生成相同帧，预算过大不导致内存压力和回收卡顿。 |

先完成 P0，再共同推进 P1/P1a 的调度与快路径，依据热点接入 P2～P5；不必等全部画质优化完成后才处理回合等待。每阶段同时比较等待、渲染和持续负载，再进入下一阶段。只有既有 Canvas 路径在真机测量后仍无法达标，才评估 Worker/OffscreenCanvas 或 WebGL；本轮不决定更换渲染框架。

## 正常演出与快速结算共用流程

规则执行 → 保留必要持久化/恢复点 → 合并表现变更 → 按模式刷新。内部仍逐步执行合法行动，但不要求每一步都完整传输快照、重建 HUD 和绘制战场；具体批次与数据协议以测量和一致性验证决定。

| 状态 | 规则推进 | 表现与刷新 |
| --- | --- | --- |
| 正常操作/演出 | 保持原行动和事件顺序。 | 可见对象按实际动画需要刷新，复用无变化图层。 |
| 跳过回合 | 有界批次执行，保留错误处理及原有检查点；在玩家回合、胜负或需交互事件处停止。 | 省略中间演出对象与动画等待，进度低频更新；批次结果按需显示，停止边界立即同步完整可操作界面。 |
| 遮挡/后台/锁屏 | 按既有暂停语义处理，不因绘制暂停额外推进回合。 | 停止无意义绘制；恢复时同步正确状态，不补播积压中间动画。 |

优化不能只减少 `setTimeout`，也不能只降低 FPS：需要一起减少演出创建、状态传输/安装、DOM 更新、缓存失效和重复绘制；若 AI 规则计算才是主要耗时，则单独优化热点并核对规则结果。缩短结算可能提高短时 CPU 利用率，是否减少耗电与发热需以同机持续测试确认。

## 减少哪些对象

“减少渲染对象”指减少每帧处理和绘制的表现对象，世界中的部队、设施和规则对象仍完整保留。

- **屏外对象**：从可见列表排除，保留规则计算和表现过期时间；重返视野不补播过时特效。
- **不变对象**：单位待机本体及不变装饰合成缓存，地图/建筑/文字按数据版本缓存，避免相同结果每帧重建。
- **重复装饰**：同一徽标/血条组合复用图像；与动态脉动分开，不能因缓存冻结“可行动”提示。
- **次要动效**：低功耗档降低旗帜、目标圈和徽标动画更新频率，减少烟雾/火焰粒子和透明覆盖；保留可辨识的着火/士气/行动状态。
- **缩远细节**：优先简化难以辨识的军衔小图、重复边框和装饰层；敌我关系、关键目标、选中与攻击提示、必要国旗保持可见，避免再次造成“缺旗”等显示问题。
- **被遮挡界面**：只调度当前可见且需要变化的菜单/预览；弹窗仅部分遮挡时，不误停仍可见的动态内容。

## 时间与规则边界

渲染频率与逻辑步进分开，动画按时间推进；降低 FPS 不得降低移动速度、改变攻击/死亡顺序或影响随机数。屏外裁剪不得跳过规则效果或有语义的事件。

暂停、锁屏和后台切换需停止无意义绘制，并明确处理已有演出等待；恢复后按统一时间基准继续或结束表现，不积累帧补播、不自动多走回合、不误选事件选项。剧情/选项仍在原有需要玩家操作的位置停下。

RW-03 的 AI 批处理、状态同步及持久化边界纳入本联合规划一起设计；合并前端刷新不等于合并或删除规则步骤。减少请求/快照前需核对动作顺序、revision、事件中断、崩溃恢复和存档语义，不以整轮结束才保存替代现有恢复能力。批次需有步数/耗时上限及让出执行机会，避免跳过时界面无响应；不引入新的规则或自动选择事件结果。

## 真机验收

在同一设备、相同 WebView/亮度/屏幕刷新率/供电状态及近似初始温度下比较；充电测试与非充电测试分开。记录设备和版本信息；先做短场景定位，再做至少 20～30 分钟持续运行，检查热降频后体验。温度记录需区分电池温度、系统热状态及机身测温，不能相互替代。

| 场景 | 重点记录 |
| --- | --- |
| 静止战场、无动画界面、菜单和弹窗 | 主动绘制/唤醒次数、CPU 占用、内存与温度变化；确认没有无效满速重绘。 |
| 大征服密集部队、平移缩放 | 全量与可见对象数、绘制次数、排序/分配、缓存重建、帧耗时及帧间隔 P50/P95、连续卡顿与触摸响应。 |
| 近战/海战、集中火焰烟雾 | 峰值粒子/透明层、CPU/GPU 工作、峰值内存，观察攻击、伤害、死亡、旗帜和目标提示。 |
| 普通过回合与全部跳过 | 相同初始状态/随机状态下，点击至恢复玩家操作的总耗时、规则/桥接/解析/HUD/缓存/绘制及持久化耗时、请求和绘制次数；核对结果和中断恢复。分别定位瓶颈，同时验收等待与渲染收益。 |
| 切后台/锁屏后恢复、切图/切 Mod | 后台绘制及耗电、恢复正确性、缓存释放、无黑屏/残影/重复演出或状态丢失。 |

待 P0 基线完成后制定量化改善门槛，不预先承诺固定 FPS、温降或耗电降幅。30fps 档候选帧预算为 33.3ms，60fps 为 16.7ms，需同时观察长帧和输入延迟；限帧本身不能算卡顿问题已解决。最终以同机持续实测和用户体验确认验收。
